# 行程有解

多 Agent 个性化旅行规划项目。当前版本为**正式旅行画布与05B受控接线阶段**：需求输入、校验、摘要、版本1保存恢复、候选资料、离线草案与逐人核查已可体验。真实单次规划/地图的HTTP及页面接线已用替身验证，真实业务验收尚未通过（地址2次：1次匹配通过、1次合同失败；模型/道路/SDK未调用）；多Agent未实现。输入格式通过或部分道路成功都不等于旅行可行。

已实测 Node.js **24.19.0**、npm **11.17.0**；支持Node.js 24系列。本阶段应用无第三方依赖，无需安装依赖或配置账号。

浏览器打开 **http://127.0.0.1:4173**。终端按Ctrl+C停止服务。端口4173被占用时先停止此前的本项目服务。不要直接双击HTML文件；请固定使用该地址访问，换浏览器、端口或localhost域名会使用不同存档。

## 三步验收

1. 点击“编辑旅行条件”展开面板，再点击“检查并确认需求”。核对太原3人、2026-11-07/08、每天09:00～18:00、公共集合点往返，以及三人分别的偏好、每人600元与每天6公里上限。检查通过自动切换并定位摘要，仍标明旅行可行性未验证；可返回编辑。正式页面采用沉浸式画布、同行者概览和可展开编辑；日切换复用当前条件与已有结果，不自动请求。检查后关闭编辑并定位摘要，手机保留关闭入口和底部表单操作。
2. 只修改同行者1的预算或偏好，再检查；同行者2、3保持原值。点击“保存需求”，刷新后应恢复该修改。再尝试1人1天和6人3天；新增成员需要填写个人偏好，减少人数/天数先确认。预算是全程个人上限，改变天数不会自动调价。
3. 清空某人的预算或将返回时间改早，点击检查，应显示中文字段错误、保留输入，不显示通过。恢复按钮也会先确认替换当前未保存输入。程序自动测试另覆盖损坏/不兼容存档和显式覆盖路径，无需用户破坏自己的存档来验收。

## 存储与数据边界

- 手动保存有效需求至当前浏览器localStorage，键名 `xingchengyoujie.requirements.v1`，格式版本1；无存档时预填固定测试需求。
- 页面重新打开时尝试恢复；损坏或版本不兼容会提示并保留旧存档和当前输入，必须明确确认才可覆盖。浏览器拒绝存储或空间不足时显示失败，不声称保存成功。
- 无痕浏览、浏览器清理或更换地址可能丢失存档；当前没有文件导入导出、云端同步或数据库。无效表单不保存，不会覆盖已有有效存档。
- 不收身份证、联系方式或真实住宿，不保存服务商地图数据。起终点只有名称及已有地址线索，没有坐标。
- 首次接口探测是独立历史实验，不作为05B真实验收。普通/离线模式不读.env、不请求外部业务；只有显式真实准备模式读取本机配置，仍需新的本地授权文件和账号费用边界。静态白名单不暴露配置/仓库/私有材料；SDK外网策略仅用于真实准备模式。

## 工程与复现说明

- `web/core.js`：纯函数输入转换、结构校验及版本化存储，供浏览器和测试共用。
- `web/app.js`：工作台视图、原生折叠、字段错误导航与摘要、按操作配置的确认弹窗、保存脏状态。日期由开始日期和天数唯一计算；需求数据中以连续每日日期为准。成员保留稳定ID，增加成员使用随机UUID，删除需确认。
- `server.mjs`：Node内置HTTP服务，仅绑定127.0.0.1，不读取密钥；提供固定本地API、同源/Host校验、32KB请求体限制与脱敏错误。
- `data/taiyuan.mjs`：4候选与逐字段证据；`lib/planning.mjs`：匿名交接、严格草案合同、核算与有界离线测试管线；`lib/offline-fixture.mjs`：仅显式测试服务启用的替身，按候选顺序分配日期，不做个性化优化。
- `tests/`：内置单元/服务测试与独立浏览器回归。
- `package-lock.json`：无外部应用依赖的锁文件。页面字体使用系统字体，无远程CDN、图标库或素材。页面与业务代码为本项目编写；Node测试工具为内置功能。Playwright作为独立验证工具，项目来源https://github.com/microsoft/playwright（Apache-2.0），未复制其实现进仓库。
- `.env.example`：仅供后续服务端接口验证使用，当前页面不需要；真实.env不得提交。不要为体验本阶段重跑scripts/verify_api_access.py（它会发计费请求）。

可重复的是固定需求默认值、校验规则、存储格式与测试输入；用户后续修改、随机成员ID和保存时间不保证逐字一致。当前无需模型，不涉及模型输出确定性承诺。完整AI对话导出/截图需另行留存，进度摘要不能替代原始链路。
