## 核算口径

已确认：共同游玩，不分队；个人预算是全程餐饮、门票、市内交通上限，排除住宿和往返太原大交通；每日步行包括交通接驳与场馆内部，每天包含出发和返回集合点交通。预算与步行逐人检查，不互相抵销，不擅自放宽6/4公里或其他用户输入。

建议以下保守区间口径，待确认后实现：

- 时间使用北京时间旅行日期、分钟计算。计划起点＋去程＋游玩/用餐＋接驳/等待＋相邻交通＋返程，逐项累加，不允许漏返程。道路秒数向上取整分钟，游玩估计限定候选区间；排队/候车未知保留未知，API若已含某等待不重复加。模型只提顺序与停留估计，程序计算到离时间并检查重叠、当日窗口、已知开放与停入时间；资料来源只覆盖常规时间时，日期可执行性仍未知。
- 费用以整数分运算，显示元两位；估计保留上下界。门票与餐饮各人分别计入，公交地铁按每人票价；缺价格不记0。若将来启用共享车辆，须另确认容量、车辆数及分摊，本批建议不启用。
- 步行以米累计再显示公里，不按展示四舍五入值判上限。共同道路步行＋接驳＋每人内部步行，不把同一公交结果的总步行和分段再次相加；内部/道路重叠须去重，无法明确则资料不足。
- 区间下界已超上限为冲突；下界未超但上界超出为不确定；资料齐全且上界未超只能说明“按当前估计未超”。任一项未知即保留该项未知；已知下界仍可指出确定超支/超时/超步行。整体存在未知就不能显示行程可行；结构通过、估计核算、真实可执行分开。

## 模块交接

需求校验（服务端复用并限制体积）→资料模块（带证据状态的固定候选）→单次模型规划（匿名需求、候选ID、顺序和停留估计、缺口与简要依据）→结构拦截（禁止新ID/坐标/票价/营业事实）→地点及道路适配（固定服务、同一高德坐标口径、各日出发/相邻/返回段）→程序核查（逐人费用/逐日时间步行及缺口）→地图与列表。

任何入口未匹配或坐标歧义停止对应路段，不用机构中心点冒充入口。真实道路几何来自服务，不由模型绘制；午餐无定位时显示缺段，不连成完整路线。错误按结构无效、冲突、资料不足、接口失败分别呈现。一次模型请求只称单次生成；多Agent职责与多轮编排仍未实现。

版本1只保存用户需求；模型草案、道路与几何分开管理，未核对许可前不持久化地图原始数据。刷新不自动重新请求，切日只重用当前会话已有结果；旧草案不应用到修改后的需求。保留04交互，并在05复查摘要从下方滚动/错误修正进入时的可见性，属于功能回归，不另做美化。

当前新授权为0：不调用模型、地点、道路或加载地图SDK；可在取舍确认后先做离线实现。首次1元授权不延续。以下仅是建议上限，不是授权：

| 类型 | 单轮联调建议硬上限 |
| --- | --- |
| 模型 | 1次；输入最多8000 tokens（本地预估不能确保时按字节保守拦截），输出最多2000 tokens；45秒超时；修订0、重试0 |
| 地点解析 | 最多5次，覆盖集合点与4候选；每次15秒；不得失败后自动改地址重查 |
| 道路 | 最多12次，包含所有日期去程、相邻、返程及任何方式切换尝试；每次15秒；超额缺段停止 |
| 地图初始化 | 最多1次，用户明确触发才加载；SDK自发瓦片/资源请求另计，初始化次数不是HTTP总数或费用硬限额 |
| 全流程 | 并发1，总运行最多180秒；无自动重试、修订、充值；终止后不再启动下游请求 |

预算须由用户另给总人民币上限；按当期价格、账户权限/余额/用途/配额、展示缓存条件和已扣留额度预检，不能证明受控就不联网。SDK无法仅靠应用计数保证账单上限，无法落实账户侧限制或费用边界时不初始化，保留待联调。限额要覆盖本轮所有操作及重启，不因刷新/切日重置；超时已发送仍计一次，取消不保证供应商不计费；记录脱敏阶段/次数/token，不记录密钥URL。

缺配置/授权、输入无效、未知ID、结构或体积超限、权限/计费不可确认、上游失败/超时/额度耗尽立即结束对应阶段并报告。语义冲突不自动再叫模型或换交通绕过；不保证两天全路线都能在上限内完成。官方价格与账号许可尚未在本轮联调前复核，因此不报告预计费用或可调用。
