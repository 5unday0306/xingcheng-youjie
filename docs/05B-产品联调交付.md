## 实际问题与修复链

- SDK完成事件出现但灰底：最初HTTP200的get_tile只是地址清单，不是实际瓦片。增加Worker瓦片地址诊断，用户批准固定路径后真实底图出现；旧灰底截图/报告保留，没有当通过。
- 缩放/拖动后SDK日志新增label/value，被旧初始化代理参数合同拒绝。仅兼容这两个已观察字段，保留固定上游、长度/回调/重复参数保护。
- 公交响应含via_stops/alters/spaces空铁路信封，旧代码按有键便拒绝。合成用例只接受无实际铁路数据的空值，实际列车信息仍拒绝；修复后公交真实查询成功。前两次道路没有保存具体诊断，不倒推其全部根因；第三次统计诊断单独保留。
- 第一次真实模型JSON未过PLAN_SCHEMA；未保存原响应，具体根因未知。明确version=1、精确字段、停留范围、午餐结构，增加脱敏分类，再次真实调用通过，没有把无效输出改成成功。
- 加强合同后6人3天输入一度超体积上限。压缩模型侧重复字段，完整来源仍在资料与核查模块，保留失败TAP并恢复测试，没有放松8000字节保护。
- 断电暂停后四点/交通方式仍在，续建授权保留原21条记录/73分。恢复时地图在屏外，懒加载未完成，补加载时滚入视野；旧失败留存。
- 子页遗漏标记CSS、手机截取早于重绘、地图说明仍显示首段、生成后地图点击定位到落点卡而不是活动行，均已修复并实际复查。
- 增加运行内历史回放和显式地图重载；需求/落点/方式修改清缓存。在途需求变更以revision和取消信号丢弃旧结果，不把用户取消当接口故障，不退已发送次数。
