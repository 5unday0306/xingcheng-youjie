# 最终产品收尾验收

日期：2026-10-30。范围为太原1～6人、1～2天、有来源四处游览候选与两日餐饮。没有新增城市、主题、视频或PDF。原采用方案保持，真实预览须用户明确接受。

## 本轮实际实现

- 优先核查每天含游览的小组合，再比较更丰富安排。无硬数值风险的候选中优先避免空游览日；不能为保留游览而绕过硬约束。仅午餐及往返显著标为取舍，提供本轮实际核查的替代选择及缺口，不称全局无解。
- 用户追加决定“时间和路长限制不重要，可以让AI动态调整告诉用户”。新增显式开关“允许AI调整每日时段与步行目标”，保存/恢复/导出保留；未开启的旧需求仍严格。模型各角色收到硬/软区别，程序仍核算原目标与实际估计，预览明确显示目标、区间和增量。预算、午餐锁定、道路事实与未知不放宽；用户明确接受才改变采用版本。
- 同服务30分钟有效道路缓存复用，不从私有证据或截图恢复几何。生成次数用尽与查看已有采用版本分开；授权、SDK和道路额度仍保护。
- 博物院停留上下界传入模型函数提交schema；本地校验仍保留。阶段诊断只记录固定来源/路径、HTTP状态、阶段及耗时，不含查询参数。
- 批次剩余道路额度到边界时，只将完整核查候选交给规划/审查，不再为了第8个未完成候选丢弃已取得结果。接口真实失败仍停止，不自动重试。

## 失败与修复过程

1. 浏览器录屏组件缺失ffmpeg，未进入页面、无业务调用；本轮保留实际截图，不下载组件或更新最终视频。
2. P第一次返回为完整合法JSON，博物院停留120低于资料150。本地拒绝并阻止下游；新增来源区间schema及本次结构回归，后续真实P成功，不代填缺失字段。
3. 第二个SDK会话初始化代理UPSTREAM_FAILED停止。旧诊断不能区分网络/HTTP/读取/JSON，不推断根因；新增脱敏阶段诊断。恢复会话底图加载成功，不把它称为已定位旧失败根因。
4. 恢复W在7候选完成后第8个触及总道路限额，未发超额请求，未交规划审查。修复剩余额度保护并补回归；获额外一次启动/21道路明确授权后，最后W完成审查，额度与历史不清零。
5. 停止原因原提示误说账号未确认，改为明确“此前接口加载失败，当前运行已停止”；保留既有错误码兼容调用方。测试曾因改错误码出现5项失败，恢复代码兼容后通过，失败事实保留在聊天。
