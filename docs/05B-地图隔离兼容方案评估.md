# 05B 地图隔离兼容方案评估

2026-10-26。起点018a5ff。本轮为公开文档核查、安全诊断修正及本地替身评估；不代表真实高德兼容通过，不追加授权、不加载SDK、不读取真实.env、不修改私有账本。

## 结论与待决定项

推荐采用**独立来源、自有地图页面、最小结构化消息、服务端独立约束**的方式；主工作台保留严格CSP。先决定是否仅给地图子页面增加字符串编译能力，不能只因套iframe就视为安全或兼容完成。

候选最小放宽为仅地图来源的script-src增加unsafe-eval；主页面不增加，地图页面也暂不增加unsafe-inline，不开放任意脚本来源。M3的inline拦截影响仍待验证，不能承诺仅这一项就能加载。用户尚未决定，本轮没有在任何运行中的主页面、真实地图页或离线原型中启用这项权限。

另一个选择是继续维持全部严格策略，先向高德确认受支持的CSP兼容路径；这会继续阻塞真实底图。不能用静态地图或文字路线代替最终交互式地图，也不擅自换供应商。

## 2. 推荐部署及来源边界（正式集成尚未实施）

本地建议父页面http://127.0.0.1:4177，地图页http://127.0.0.2:4184。不同IP主机和端口形成不同来源；不用仅换同主机端口来宣称Cookie也隔离。当前替身评估用这两个IP的随机端口，固定体验端口为4185/4186，不是正式地图。

正式部署使用两个HTTPS来源，地图来源专用，最好不同站点，例如占位域app.example.test与maps.example-map.test（不是真实部署地址）。父端Cookie仅host-only，不设置共享Domain，不依赖document.domain。地图来源不托管需求编辑、账户或其他项目文件，不共用localStorage或业务Cookie。不声明因此获得独立OS进程或crossOriginIsolated。

主页面只增一个精确frame-src；脚本/连接仍本机，移走主页面直接加载SDK的职责。地图页面的CSP由专用响应头设置，不由消息或客户端参数拼接。主页面与地图页都设置Referrer-Policy: no-referrer。

iframe及地图响应头sandbox均拟为allow-scripts allow-same-origin；后者使消息保留可核对的真实origin，**不代表地图与主页面同源**。若删掉same-origin会产生不透明来源，使当前精确origin协议不能直接使用，不能改成接受所有null来源。

不加allow-forms、allow-popups、allow-top-navigation、allow-downloads、allow-storage-access-by-user-activation等；拒绝定位、摄像头和麦克风。地图页frame-ancestors只允许主页面。iframe导航/来源变化、握手超时或销毁均使本次run失效，不自动换页、重载或补发调用。

## 3. 权限变化、风险与候选CSP

以下仅是**待用户决定的配置说明**，不是当前已生效策略：

| 部分 | 拟定边界 | 影响/待验证 |
| --- | --- | --- |
| 主页面 | script-src/connect-src仅self，frame-src仅专用地图来源 | SDK不再能直接访问主页面DOM或存档；不是全站放宽 |
| 地图脚本 | self、webapi.amap.com/maps、jsapi-service.amap.com/mapsplugincdn等已核实必要脚本路径；仅script-src候选增加unsafe-eval | 允许地图环境字符串编译，降低该环境注入防护；它不保证SDK能运行。路径、重定向或新依赖不匹配则停，不自动扩域 |
| 地图inline | 暂不允许unsafe-inline，事件属性不允许 | M3中javascript:仍可能被拦；如果影响必需功能，需要先确认具体影响再单独决定，不预先全开 |
| WASM | 不因wasm-eval特殊值新增网络路径；若JS字符串编译已放开，不能误称仅允许了WASM | 仅wasm-unsafe-eval无法解释/解决已观察到的JS eval拦截 |
| 地图网络 | self受限代理及核实的SDK/图面资源；明确排除restapi.amap.com及道路服务端点 | M3没有保存全部成功资源域，精确图面依赖清单仍缺；不能把*.amap.com全放开后声称业务调用受控。下一次仅收集脱敏域/路径/类型补证据，未知来源不自动放宽 |
| 对象/嵌套页/表单 | object-src、frame-src、form-action为none，base-uri none | 不提供任意嵌套浏览器或表单发出通道 |

第三方SDK在自己的环境仍能看到交给地图的坐标、公开地点名、所显示路线与交互。隔离不是零数据外传保证，必须最小化传递；CSP允许的SDK网络也不是每个HTTP都能由应用精确计费，账号侧权限与费用边界仍必要。

如果拒绝任何字符串编译权限，本轮证据不足以承诺JS API 2.0可用；优先向官方确认支持路径。nonce/hash不能自动修好SDK内部字符串编译；不本地改写SDK绕过，不靠浏览器安全开关。静态图仅能作为另行接受的降级方式，不满足05B最终目标。

## 4. 数据及消息合同

仅发送经过投影的展示数据：地点id、公开短名称、坐标、序号，已查询几何的分段与交通方式、选中id。只允许明确展示的缺段，不补直线。不得直接传整个请求/草案对象：个人需求原话、预算、约束明细、住宿个人信息、服务端密钥均不发送。

消息外层固定v、runId、seq、type、payload。接收必须同时匹配精确来源、对应iframe.contentWindow/parent窗口、当前runId、合法递增序号及严格数据结构。拒绝多余字段、未知类型、越界坐标、重复id、过长名称、超限几何或大消息。首版仅太原测试框，不能宣称全国支持。

目前可复用的原型协议在web/map-frame-protocol.js，**未接入正式工作台**。展示最多64点/128段，总几何点最多10000且消息最多64KiB；超限拒绝，不能静默删路段后称完整。页面用textContent，不把label当HTML。

| 主→地图 | 地图→主 |
| --- | --- |
| INIT、DISPLAY、FOCUS、VIEW、DESTROY | READY、SELECT、VIEW_CHANGED、CLOSED、ERROR（固定错误码） |

没有EVAL、LOAD_URL、ROAD_QUERY、AUTHORIZE或自由fetch类型。SELECT只更新主页面选中状态，不能据此确认落点或调用道路；有效id也需存在于当前数据。需求/日切换/会话变化时父端废弃旧run和旧显示；销毁移除监听与iframe，迟到消息不激活旧结果。

## 5. 代理、调用与停止的实施约定

建议首版仍单机、单活跃地图会话：两个HTTP来源可由同一Node进程提供，但仅通过内存内部接口/受保护的服务端通道共享受控适配器和持久账本。不是把跨源业务API对地图开放CORS。

用户在主工作台明确加载后，服务端按新授权先预留SDK次数和费用、登记当前run及期限，再允许该地图页一次性取得自己的bootstrap配置（只有公开JS Key及自己的serviceHost）。runId只用于绑定，不是续期或授权；页面刷新、重启和重复bootstrap须由持久记录拒绝，不能重新发SDK。首版不得将此单活跃设计冒充多用户会话隔离。

地图服务同源的/_AMapService只转发已核实初始化路径和参数，固定上游、固定账号public key匹配，安全密钥由服务端附加；不提供任意URL、host、路径或代码代理。每次代理核对主账本停止、有效期及会话。拒绝外部来源，不能只靠“iframe来自我方”跳过服务端限制。后续如必须增加样式等代理路径，另核用途再审阅，不自动接口回退。

不共享父端mapLease Cookie，也不把方案建立在第三方Cookie一定可用之上。单机单活跃方案可由服务端内部绑定run和一次性bootstrap，验证同源请求环境；不能仅凭可猜runId或路径允许转发。正式跨站部署的一次性bootstrap与重放持久性仍需实现和验证；当前原型不冒充已完成安全代理。

道路继续只由主页面明确按钮→主服务受控适配器发起，独立校验次数/费用、需求版本和停止。地图页不能提供路线服务插件、直接Web服务或道路代理。用正式createServer验证来自地图origin的道路/许可/初始化请求返回403，模拟后端调用次数0；这是跨源保护验证，不能替代未来专用代理的完整验收。

失败/超时/新未知必需权限立即停；移除地图iframe，服务端使run及代理许可失效，原计数/费用保留。不因READY/SELECT/刷新而续期或清SDK_FAILED。帧销毁不等于已发网络请求退款。

## 6. 本轮已实施的小修正

- 诊断将inline/eval/wasm-eval等特殊值作为类型保存，path为空；M3旧证据不改写。原生浏览器测试触发这三类事件，未再把wasm-eval当网络路径。
- 正式选点面板开始加载时显示“正在加载真实地图”，不一直显示“尚未加载”。
- /favicon.ico单独返回204，消除本机缺图标404；不将其作为地图渲染修复。
- 真实CSP未放宽；正式应用没有自动启用iframe或加载SDK。
