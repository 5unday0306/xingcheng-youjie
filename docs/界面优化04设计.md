## 1. 本轮目标与边界

把“能填写需求的后台表单”改成“有目的地识别、同行者温度和清楚操作路径的旅行准备产品”。视觉效果要有实质变化，同时保留任务03已完成的交互。

本轮交付包括布局、排版、目的地意象、同行者展示、需求摘要和状态反馈。地图和行程生成仍是后续必须完成的产品目标，但本轮不接接口、不请求模型或地图、不读取密钥。UI优化不能被记录为路线生成已完成。

不能只修改配色、边框、圆角后沿用大块空白；也不需要重建整个应用、换框架、引入账号体系或搭建营销首页。

### 已确认的产品内容

- 产品名称：行程有解。太原是首个试点，当前只提供太原的测试入口。
- 人数1～6、天数1～3，每位同行者分别填写偏好、预算及每日步行上限。
- 默认测试：三人，2026-11-07至08日，每天09:00～18:00；偏好为历史展览、风景拍照、美食少走路。
- 每人全程600元，包含餐饮/门票/市内交通，不含住宿和往返太原大交通；每日步行上限6公里。
- 两天均往返山西博物院东门外公共集合点，不是住宿或已核实现场入口。
- 保存恢复、字段错误导航、减少人数/天数确认、本人步行复制确认和版本1存档已经实现，必须保留。

长期希望向更多地区扩展，当前确认的第一版仍是山西省内少量城市。不要把“太原试点”写成永久地域限制，也不要展示虚假的全国城市可用列表或覆盖数字。

## 3. 视觉方向与设计标记

采用“旅行准备册”的方向：轻盈、清楚、有目的地气质，适合一起出行的年轻用户。用一处有辨识度的目的地意象作为主要视觉，其他内容保持克制；不添加无功能的侧边图标栏、仪表盘统计、营销轮播或大片渐变。

以下为推荐起点。开发可依据真实截图微调对比度与比例，无需把常规视觉选择反复交给用户确认；不得改变本文的功能边界和验收目标。

| 标记 | 建议值 | 用途 |
| --- | --- | --- |
| 画布雾白 | `#F4F7F5` | 应用外围背景 |
| 面板白 | `#FFFFFF` | 主要内容与编辑区域 |
| 正文墨绿 | `#183D35` | 标题、正文及关键数值 |
| 操作松绿 | `#226A54` | 主按钮、选中状态、焦点 |
| 目的地浅青 | `#DCEAE1` | 插画底色与轻量分区 |
| 辅助青灰 | `#64746C` | 辅助说明，仍须满足实际对比度 |
| 点缀杏黄 | `#E7B963` | 小面积装饰；不单独承担警告语义 |

- 中文使用本机Microsoft YaHei等清晰无衬线字体，数字优先Segoe UI。用字级、字重、对齐形成差异，不引入外网字体。
- 桌面目的地标题建议30～36px，区域标题18～22px，正文14～16px，辅助说明至少12px；手机标题24～28px。不要把主要字段标签、错误或按钮降为10～11px。
- 间距以8px为基础，字段12～16px、模块20～24px；同行者条目、主面板和标签采用不同层次的形状，不把所有元素做成同尺寸圆角卡片。
- 兴趣标签可少量使用不同底色，但含义必须有文字，不依靠颜色区分人物或错误。

### 素材原则

优先原创CSS/SVG城市意象：可参考山形、屋檐、塔形和旅行票签的形式，作为非地理性的装饰。它不是地图、现场实景、景点精确复原或路线，旁边简短标明“城市意象插画”。不得绘制仿真地图底图或假道路来填空。

不使用未经核查的景点照片、远程头像、外网字体或抄来的旅行产品整页模板。若确实增加其他素材/图标，先记录来源与适用许可证；不为美化默认安装全套UI框架。

## 4. 信息结构与布局

### 桌面（主要参照1440×900）

保留左右工作区，但改变右侧内容和视觉重心。左栏约330～370px，右侧自适应。顶栏约64～72px，品牌与当前阶段清楚即可。

```text
行程有解  /  旅行准备                                  太原试点
┌需求编辑──────────┬目的地横幅─────────────────────────┐
│出游条件           │太原 + 实际日期/人数/天数   城市意象 │
│每日时段           ├路线准备 / 需求摘要─────────────────┤
│同行者折叠条目      │日切换                              │
│每人的需求和限制    │紧凑路线未接入状态   当天出行条件    │
│必要说明可展开      │同行者需求概览（来自当前输入）        │
├固定操作区────────┤待核实资料（可展开）                 │
│检查并确认需求      │                                    │
│保存 / 恢复 + 状态  │                                    │
└──────────────────┴────────────────────────────────────┘
```

- 右侧顶部目的地横幅建议140～180px高，信息与插画各有空间，不能做成占半屏的宣传海报。
- 首屏应看到目的地、日期、至少一项真实同行者信息、明确主操作或下一步状态；不能只有表单和大块未生成提示。
- 不重复并排显示完整大日期、人数/天数和同内容统计卡。日期、人数变化时，由同一份当前需求数据更新，不能在横幅写死“三人两天”。
- 左侧需求可独立滚动，底部操作不遮挡字段。右侧至多一个主要滚动容器，避免每张卡片各自滚动。
- 右侧切到摘要后，用完整宽度显示核对内容，不能让窄卡片造成大量折行。

### 手机与平板

- 手机保留“编辑需求 / 需求摘要 / 路线准备”视图切换，当前视图有文字和选中态。
- 编辑视图优先填写，目的地装饰缩小或隐藏；不能为了插画把主操作推出屏幕。
- 摘要视图显示目的地和逐人需求，提供明确返回编辑入口；路线准备视图只展示真实当天条件和未接入状态。
- 窄屏同行者卡片一列，触控目标建议至少44px；390px下正文、按钮和错误可自然换行，不裁切姓名与关键限制。
- 768～1024px若双栏过窄，优先切单工作区视图，不硬塞三栏。
- 页面缩放到200%时仍能编辑和操作。软键盘可能遮挡底栏时，确保页面/编辑容器能滚到当前输入与主操作；未真机检查需如实标记。

## 5. 重点模块设计

### 5.1 顶栏与目的地

品牌使用“行程有解”，页面阶段为“旅行准备”；目的地动态显示“太原”，用小标签“首个试点”。无需把完整参赛题名塞进顶栏。

横幅只使用当前输入中的目的地、日期、人数和天数。若日期尚未填写，显示待填写，不展示旧日期。名称与意象通过城市配置关联，避免散落在HTML和JS中反复硬编码；这是为扩展准备，不开放未支持城市。

### 5.2 同行者

- 匿名头像用姓名首字、序号或原创几何形状，不下载真实人像。
- 卡片收起时显示姓名、需求原话简述、个人全程预算与逐日步行上限；长文本可截断展示，但展开后完整保留。
- 展开后字段分组为基本信息、兴趣与需求、步行限制，个人预算明确是全程金额。不能擅自把原话解析成已确认的硬约束标签。
- 首位成员可默认展开，错误成员自动展开；编辑前后展开状态合理保留，输入不因重绘丢失。
- 右侧同行者概览可显示当前输入的简述及“查看/编辑”入口；有入口就必须定位到对应成员，无死按钮。

### 5.3 当天条件与路线空态

将原先整块地图占位缩为紧凑状态模块，建议160～220px高，不再充当首屏最大主视觉。日期切换保留，当天时段、集合点和个人限制来自当前输入。

推荐文案：“路线还未接入。当前可以先确认同行需求。”配合现有真实动作“检查并确认需求”或“查看需求摘要”。模块不提供假“立即生成”、假加载动画、自动跳动进度或假地点时间轴。

无真实路线时，主视图可称“路线准备”；生成接口后续接通再改为“每日路线”。只在一个位置说明“未加载地图 / 无路线数据”，不重复放多条相同警告。

待核实资料用可展开区展示，保留入口、营业预约、午餐、交通与内部步行等现有缺口。可以按问题种类分组，但不得把清单数量当作已完成进度。

### 5.4 需求摘要

摘要呈现为可核对的旅行准备单：基本条件在前，每人需求分组在后，预算包含/排除范围可展开；字段少时保持紧凑，不堆长段JSON。开发详情继续折叠。

一次明确提示“需求格式已检查，行程尚未生成”。不能将字段通过换成“行程可行”“预算充足”或“适合所有人”。返回编辑时保留所有内容和当前存储状态。

## 6. 状态与交互规则

| 状态 | 应显示什么 | 操作行为 |
| --- | --- | --- |
| 首次打开，无存档 | 默认测试需求、尚未保存 | 可以修改、检查和保存 |
| 恢复存档 | 已恢复，尚未重新检查 | 不宣称刚编辑或刚生成 |
| 修改但未保存 | 有未保存修改 | 保存状态与检查状态分别更新 |
| 输入有误 | 字段错误、错误入口 | 定位首错并展开成员，修一项不清除其他错误 |
| 检查通过 | 需求摘要与当前数据 | 自动进入摘要，不产生地图或模型请求 |
| 保存成功/失败 | 实际状态与保存时间或原因 | 失败保留输入和原存档，不能假报成功 |
| 路线准备 | 未接入、当天条件、下一步动作 | 不生成地点，不模拟运行 |

恢复、减少、覆盖存档及步行复制的确认标题和按钮必须对应操作；取消和Esc不改变数据。版本1存档继续兼容，不能以重设计为理由清空浏览器数据。

如果增加右侧快捷检查按钮，应复用现有校验入口和焦点行为，避免两套逻辑分叉。品牌链接、页签和其他点击元素必须有明确行为；不用不可操作的链接充当导航。

键盘焦点清楚，成员展开和页签选中有程序可读状态，错误说明保留aria关联。动画仅用于展开、切换等反馈，尊重减少动态效果设置。文本对比度实际核查，不能只看配色表推断通过。
