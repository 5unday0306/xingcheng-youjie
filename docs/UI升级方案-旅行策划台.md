# UI升级方案：旅行策划台

日期：2026-10-25。状态：设计提案，尚未实现、未经用户视觉验收。

需求来源：用户反馈“UI还是太简单了，换一个高端点的UI或者换一个skill”，并明确先不执行05B。本文由AI辅助整理，交给开发聊天实施；本轮不修改应用代码、不提交或推送。

## 目标与取舍

以任务05现有功能为基础，重新设计视觉语言和结果呈现。采用成熟旅行策划工具的方向：清楚的空间层级、舒展的中文排版、可扫描的逐人条件和每日活动、可信的状态表达。

选用已有frontend-design设计指导，替换旧04方案的视觉与布局要求。无需为了换风格重建技术栈或安装另一个Skill。若开发判断确需额外工具，先说明它解决的具体问题，检查来源与许可证，不直接安装完整模板项目。

本方案对视觉与布局的要求优先于旧04设计；输入结构、保存格式、业务校验、确认保护等已实现功能继续保留。05B真实接口、地图、Agent协作与重排不在本轮范围。

## 从现状到新方案

审阅依据为docs/verification/task05-offline-1440.png及现有04设计说明，并非本轮新浏览器回归。

| 现状 | 本轮设计变化 |
| --- | --- |
| 左侧长表单占据固定主体 | 左侧成为需求清单：旅行条件与同行者概要可扫描，编辑时展开对应部分 |
| 浅绿背景、边框和提示相互接近 | 瓷白工作面、深蓝结构区与清晰正文形成层次，状态色独立 |
| 简笔插画横幅占据结果上方空间 | 顶部改为紧凑旅行标题区；品牌图形以原创行李标签、日期票签等旅行元素形成辨识度 |
| 结果像文档或日志 | 每日安排采用纵向活动序列，核查结果有清晰的公共信息与个人信息分区 |
| 大量说明重复出现 | 公共缺口集中展示；个人区域保留个人限制、已知部分和冲突；详细来源可展开 |

不要通过隐藏风险、减少必要字段或虚构活动来获得简洁。

## 视觉系统

| 角色 | 建议色值 | 使用方式 |
| --- | --- | --- |
| 深蓝 | #173247 | 顶栏局部、标题、主按钮；避免整页黑底 |
| 瓷白 | #F6F8FB | 页面画布 |
| 纯白 | #FFFFFF | 主工作面与编辑面板 |
| 正文 | #202D3A | 正文与主要数据 |
| 次要文字 | #526477 | 辅助说明，实际测量对比度 |
| 铜橙 | #B65C31 | 小面积品牌标记、当前日期强调；不与警告混用 |

成功、警告、错误另设语义色，文字和图标共同表达。不要做通屏渐变、玻璃特效、发光描边、金色细字或密集悬浮卡片。

中文正文优先使用本机清晰无衬线字体；目的地标题可以使用本机中文衬线字体，并提供可靠回退。避免远程字体依赖。建议标题32～40px、区域标题20～24px、正文15～16px、字段标签14px、辅助文字不低于12px。长中文段落控制行宽，重要说明不得降成浅灰小字。

采用4/8px间距基础，模块间距24～32px。主工作面圆角16px，输入与次级模块8px，标签胶囊形；使用少量有目的的边界与阴影，不给所有内容套同一种卡片。

## 桌面结构

1440px宽度参考：页面边距24px，列间距24px，左侧需求区约320～360px，中央为主要内容。1024px空间不足时转单工作区，不硬塞三列。

```text
行程有解   旅行准备                         太原试点 / 保存状态
太原 · 两日旅行                  实际日期、人数 / 当前运行模式
────────────────────────────────────────────────────────
需求清单                  每日安排                 核查信息
旅行条件概要              第1天 / 第2天             当前结果状态
展开编辑                  活动顺序                 当天时间
                          用餐待确定区段           公共资料缺口
同行者1 / 偏好与限制       活动顺序                 个人预算与步行
同行者2 / 偏好与限制       返回集合点条件           详细依据可展开
同行者3 / 偏好与限制
检查需求 / 保存 / 恢复
```

三列不是硬性要求。右侧核查区建议260～300px；中央宽度不足约束阅读或活动卡时，将核查移至中央下方，不能挤压成窄字条。

左侧编辑可独立滚动；中央和右侧尽量使用同一工作区滚动，避免三条等权细长滚动栏。操作栏不覆盖最后一个字段；所有字段、确认弹窗、错误入口可通过键盘到达。

标题区来自当前输入，不写死人数或日期。清空日期后显示待填写。不要加入无功能的搜索框、账户入口、导航栏或“分享”“导出”等尚未实现按钮。

## 四种真实页面状态

1. 准备状态：以同行者需求、当前旅行条件和下一步操作为中心。没有活动数据时不绘制时间轴节点，不放假地图，不展示预测完成率。
2. 检查通过：展示清晰准备单，保留返回编辑。明确“输入检查通过，行程尚未生成”。
3. 离线测试结果：保留醒目的“离线测试，非真实模型或地图结果”。实际候选变成可扫描的活动条目，可列出停留估计；到离时间未知就写未知，不制造09:00等精确时间。
4. 错误或资料不足：显示问题、影响和下一步。已知费用下界超限时显示冲突，同时保留总量未知，不将缺资料等同于0。

普通4173页面和离线4174页面使用同一设计语言，但能力与模式标记必须准确。不得通过UI升级启用真实调用或改变接口授权。

## 关键组件

- 同行者：每人有文字首字或原创几何头像；姓名、原话简述、个人全程预算、逐日步行限制可扫描。预算显示“全程”，超长原话可展开；不把原话自动改成已确认偏好分类。
- 活动：名称是主标题，停留估计和资料状态次之。集合点、活动、待定用餐在视觉上有差异。装饰线只表示列表顺序，不表示真实道路或已核实时刻。
- 核查：公共缺口只集中展示一次，个人特有问题在个人区域展示。全程费用标明覆盖全部日期；当天时间与当天步行随日切换，个人全程费用不随切日变成单日费用。
- 开发细节：内部ID、JSON、原始阶段记录收进详情。路段正文使用中文地点名，保留数据标识供调试，不损失未知原因与来源。
- 操作：一个主要动作，保存/恢复为次要动作。当前动作必须实际可用；不得出现假的“AI生成”“重新规划”按钮或协作进度。
- 原创图形：只做辅助品牌元素，不强制照片或插画。不得复用完整旅行产品模板。若引入图片、图标或字体，逐项登记来源、许可、用途与本地回退。

## 手机与中等屏幕

375～430px为单工作区，保留编辑/摘要/路线准备的真实视图。顶部压缩成旅行标题与日期人数；编辑状态优先字段，结果状态优先活动与核查。个人核查可纵向展开，不以横滑卡片隐藏关键冲突。

768～1024px根据实际内容使用单工作区或双栏，不能只缩小桌面字号。触控目标建议44px；错误、按钮与长中文名称可换行。手机底部操作栏要留出页面空间，检查安全区域；真机软键盘未验证时明确说明。

## 分两步实施与验收

第一步仅交视觉预览：在项目独立预览路径制作桌面和手机界面，使用本项目默认案例，醒目标注“设计预览”。若使用固定离线结果，标为固定样例，不调用业务接口，不替换主页面、不改存档。交付1440×900和390×844实际截图，呈现编辑状态与离线结果状态。用户认可视觉方向后，再迁移到正式页面。

第二步集成：复用已有状态、校验、存储和API边界，重组视图，避免复制另一套业务逻辑。先核对当前程序实际状态再选择回归检查，不把以前测试数量当作本轮通过数量。

视觉验收：

- 与04截图并排时，布局、排版和结果呈现有明显改变，不能仅换配色和横幅。
- 1440px首屏可找到目的地、日期人数、同行者入口、当前模式和主要操作。
- 离线结果中的活动名称、资料不足、当天/全程区别和个人冲突容易找到；公共说明不逐人重复。
- 375、390、768、1024、1440px无意外横向溢出、遮挡或无法到达的操作；200%缩放如实区分原生检查与等效重排。
- 正文、按钮、占位和状态文字对比度实际测量；键盘焦点可见，减少动态偏好有效。

功能验收：默认3人2天、1人1天、6人3天；数据隔离；版本1存档兼容；保存/未保存/恢复；减少确认、取消/Esc；步行复制；错误定位与修正；修改输入后结果失效；日切换；离线运行失败与重复操作保护。

本轮不读取真实.env，模型、地点、道路、地图SDK新增请求为0。第三方设计资料的网络检索与业务调用分别记录，不能把页面外部资源请求也计为0而未实际核查。
